# Self-audit

The planned design, walked against the reference bar: `C:\Users\yuvra\wingman\scripts\audit-frontend-hygiene.mjs`
(read in full — 14 numbered sections, ~54 assertions across a 5-page set), plus the de-slop list from
the Lark waitlist rebuild and the visual tells named in
`docs/agents/reports/waitlist-competitive-look.md`.

Every item in the hygiene script is phrased as a **defect**, so PASS means the defect is absent. I
have kept that polarity. Nothing below is claimed as verified — **there is no site yet.** Every line
is a *design-time commitment* plus the observation that would falsify it. The distinction matters:
this document's job is to be checkable later, not to be reassuring now.

check goes red. Lark hit this exact class three times in one day.

## 2. The de-slop list

| Tell | Us |
|---|---|
| Eyebrow pills / kicker labels above headings | **Absent.** Zero on both surfaces. Mono mastheads are document identifiers with content (`RECEIPT 4F2A-9C`), not decorative kickers. Risk: the masthead is one careless edit from becoming an eyebrow. |
| Ping dots / pulsing status | **Absent.** The self-scan card shows `12 s ago`, a fact, rather than a green pulsing "live" dot. |
| Identical card grids | **Absent.** No three-across anything. The evidence list is a single-column list of unequal-height rows. |
| Infinite float loops | **Absent.** Zero infinite animations. |
| Per-card staggers | **Absent by explicit rule.** Beat 3 reveals the evidence list as one block. |
| Crushed letter-spacing | **Absent.** Floor of `-0.01em`. Lark shipped `-0.04em` at 800. |
| AI-serif (Instrument / Fraunces / Playfair) | **Absent.** No serif in the system at all. |
| More than one motion moment per view | **Absent.** One timeline, 500 ms, and the landing reuses the receipt's. |
| Oversized bold hero | **Absent.** 52px at **Regular 400**. |
| Template gradients | **Absent.** Zero gradients. Zero. |
| `rounded-2xl` + hairline + diffuse two-layer shadow | **Absent.** Radius 0 on documents, no box-shadow in light mode at all. |
| Shape-assembled illustration | **Absent.** No illustration anywhere. |
| Cream/beige as the "tasteful AI" default | **Mitigated, not eliminated** — see risk #2. |

## 3. Top 3 risks — adversarial reading of our own choices

### Risk 1 — The dark-mode-terminal-forensic look is itself a genre, and it is a dev-tool genre

Mono type, zero radii, no shadows, hairline rules, a single cobalt accent, `PASS` in a fixed-width
column. I have described "the 2024 developer-tool landing page." Cursor, Linear's changelog, Railway,
half of Vercel's ecosystem and a very large number of *generated* dev-tool sites all live here. I
avoided the cream/AI-tasteful cliché by walking into the adjacent one.

Why I still think it is right: the layout is genuinely derived from the artifact (a receipt is a
document; documents have square corners, mono locators and no shadow), and one honest structural
metaphor beats an arbitrary differentiator. But the defence is *derivation*, and derivation is
invisible in a screenshot.

**Falsifier:** put the landing page next to five current dev-tool homepages at 1440px. If a stranger
cannot say which is ours in three seconds, the objection is proven and we need the one non-UI brand
artifact the comparables all have (Amata's photographed handwriting, Rodeo's joke domain, Overtone's
1,854-word essay). My candidate: the **printed physical receipt** — actually print one, photograph it,
and let that photograph be the only image on the site. Not designed yet. Flagged as the largest open
gap in this foundation.

### Risk 2 — "Zero findings on our own site" is the strongest asset and the biggest liability

The plan publishes a live self-scan in the fold. The first skeptic will not run our detector on us —
they will run *someone else's*, or read our CSS by hand, find one thing our corpus does not encode,
and post it. `0 findings` then reads as a rigged benchmark, and the whole honesty posture inverts in
one screenshot.

There is also a quieter version: because we know our own rules, we can trivially design to pass them.
That is teaching to the test, and it is exactly what we accuse everyone else of doing with detectors.

**Mitigations, all of which need to be decided before launch:**
- Never render the number as a badge or a score. `0 findings in 54 checks` with the checks enumerated
  is a measurement; `100/100` is a boast and is indefensible.
- Ship a permanent, linked **"what our own scan cannot see"** section listing the tells we know we do
  not encode. Volunteering the gap is the only credible position.
- Consider deliberately **not** fixing one cosmetic finding and publishing why. A page that scores
  perfectly on its own tool is less believable than one that scores 1 and explains it.
- Never claim the self-scan generalises. It is 54 hygiene checks, not a verdict on our taste.

### Risk 3 — The equal-prominence disclaimer degrades exactly where it matters most: the export

The whole distribution strategy is "the side-by-side is the screenshot." Which means the artifact
that travels is a PNG, rendered by a code path (`og:image`, `Export this receipt`, a user's own
`Cmd+Shift+4`) that is not the code path the legal review looks at. Three concrete failure modes:

1. The OG image generator lays out the two panels at 1200×630 and the disclaimer does not fit, so
   someone shrinks it to 10px "just for the card." That is the precise defect the legal research
   names as insufficient.
2. A user screenshots the panels alone by cropping. We cannot prevent it, but we can make the
   *default* crop include the band — which is a layout decision (band inside the border, band tall
   enough to be in any sane crop) and needs testing at 4:5, 16:9 and 1:1.
3. The disclaimer renders correctly but the two panels are visually asymmetric — different plate
   sizes, a highlight on the recreation, an arrow between them. The layout then makes the accusation
   and the words underneath cannot retract it. The spec forbids this; nothing enforces it yet.

**Falsifier:** an automated test that renders every export size, OCRs the output, and asserts the
disclaimer text is present at ≥ the panel-label pixel height. Not written. This should be the first
test in the repo, before any detector logic, because it is the only one whose failure is a legal
exposure rather than a bug.

## 4. Smaller risks worth writing down

- **Diatype is unbought.** Every claim about the shipping typeface is currently a plan. Until the
  Dinamo licence is purchased the site runs the system stack — and a system-stack site will read more
  generic than the mock. Do not launch in the interim state and call it the design.
- **`system-ui` in a fallback stack resolves to Inter-alikes** on several platforms, quietly
  reintroducing the banned face. It is excluded from our stack for that reason; someone will add it
  back for "correctness."
- **shadcn's default theme is the tell.** `--radius: 0.625rem`, `--destructive`, `--chart-1..5`. If
  the override in `COMPONENTS.md` is skipped, we ship the most recognisable generated-UI signature in
  the ecosystem while selling a generated-UI detector.
- **`0 inferred` on the receipt is a promise with teeth.** The moment one heuristic finding ships, the
  counter must move. If it is hardcoded to zero it is a lie printed on every receipt.
- **Reduced motion.** The count-up is the entire motion budget, and the reduced-motion path must show
  the final number *rendered in the HTML*, not a value written by JS that never runs.
- **The anime.js version gap.** The MCP documents v3.2.1; `npm i animejs` gives v4 with a different
  API. Pin deliberately.
- **No mobile spec yet.** Both Figma frames are desktop. The side-by-side figure at 390px is the
  hardest unsolved layout in the product: stacking the panels vertically weakens the "same frame"
  argument, and the disclaimer must still sit inside the same border with both panels. Solve it before
  building, not after.
