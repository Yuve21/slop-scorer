# Surfaces

Two surfaces are specified here to build-level detail: the **receipt** and the **landing page**.
Both exist as Figma frames — see `DESIGN.md` §0 for URLs.

Governing product rules, restated because they determine layout and not just copy:

1. **Evidence per finding, or it is not the product.**
2. **Never name a creator. Never assert "this is AI."**
3. **If the original and the recreation appear together, the disclaimer is same-size, same-prominence,
   in the same frame.** A 10px grey footnote is legally insufficient; the side-by-side layout itself
   is treated as endorsing the inference, so the correction has to live inside that layout.
4. **`inconclusive` and `not_assessed` are results, not errors.** Abstention is the feature.

## A. The receipt (verdict view)

Figma: `node-id=1-3`, 1200×1601.

### First 3 seconds

In order of visual weight, top to bottom:

1. **`8.4 seconds`** — 56px, Regular, ink. The largest object on the page is a measured duration.
2. **One sentence** at 21px: *"That is how long our pipeline took to produce the right-hand panel from
   the prompt below. A person doing the same work by hand: roughly a day."*
3. **The figure** — two panels, a hard vertical rule between them, one border around both.

A visitor who reads nothing else takes away *"they remade it in 8.4 seconds"*, which is the claim we
are legally comfortable making and the only claim the product is actually making.

What is **not** in the first 3 seconds: any percentage, any gauge, any red, any word resembling
"detected", "fake", "AI-generated", or "confidence".

### Hierarchy, top to bottom

| # | Block | Type | Notes |
|---|---|---|---|
| 1 | Masthead | Mono 12, `+0.06em` | `SLOP SCORER / RECEIPT` left; `4F2A-9C · 2026-08-23 21:44 UTC` right. The receipt ID is a real, resolvable permalink. |
| 2 | Hairline | 1px | |
| 3 | Elapsed figure | Sans Regular 56 | Animated once (motion moment, `DESIGN.md` §7). |
| 4 | Claim sentence | Sans Regular 21, max 72ch | |
| 5 | **FIGURE** | see below | The legally load-bearing block. |
| 6 | `What let us shortcut it` / `6 citations · 0 inferred` | Sans Medium 26 / Mono 13 | The `0 inferred` counter is a permanent, visible commitment: every listed item is a measurement. If a build ever produces an inferred finding, that number stops being zero and the reader can see it. |
| 7 | Evidence list | `@shadcn/item` rows | |
| 8 | `WHAT WE COULD NOT ASSESS` | bordered band | First-class, not collapsed, not a footnote. |
| 9 | Actions | `Export this receipt` (accent) / `Show the prompt and the method` (outline) | |

### 5. The FIGURE — where the disclaimer lives

One `card`, `--border-control` 1px, radius 0, white. Inside it, in a single vertical flow:

```
┌──────────────────────────────────────────────────────────────────────┐
│  SUBMITTED                    │  GENERATED BY US                     │  ← Mono Medium 14
│  ┌─────────────────────────┐  │  ┌────────────────────────────────┐  │
│  │                         │  │  │                                │  │
│  │      the artifact       │  │  │      our reproduction          │  │
│  │                         │  │  │                                │  │
│  └─────────────────────────┘  │  └────────────────────────────────┘  │
│  provided by you · 1024×1024  │  just now · 8.4 s · prompt below     │  ← Mono 13 muted
├──────────────────────────────────────────────────────────────────────┤  ← 1px --border-control
│  READ THIS WITH THE IMAGES ABOVE                                     │  ← Mono Medium 14
│  The right-hand panel was generated by us, moments ago, from the     │  ← Mono Regular 14, --ink
│  prompt listed in the evidence below. It is not evidence about who   │
│  made the left-hand panel, or how they made it. We make no claim     │
│  that any person used a generative model. What is shown is one       │
│  fact only: this artifact is cheap to reproduce.                     │
└──────────────────────────────────────────────────────────────────────┘
```

The equal-prominence requirements, made concrete and testable:

- **Same frame.** The disclaimer is a child of the same bordered card as the two panels. There is no
  layout in which the panels can be seen without it — including when the card is the only thing in
  the viewport, when it is inside a dialog, and when it is cropped by a share card.
- **Same size.** Disclaimer body is **14px Mono Regular** — byte-identical in size to the panel
  labels `SUBMITTED` and `GENERATED BY US`. Not smaller. This is asserted by a test, not by care.
- **Same colour.** `--ink` (16.6:1), not `--ink-muted`. The only muted line inside the figure is the
  meta note about the disclaimer's own contract, which is genuinely secondary.
- **Same in the export.** `Export this receipt` renders the figure **including the disclaimer band at
  the same 14px**, in the same border. The share image is the distribution channel, so the export
  path is the one that actually matters legally — a compliant web view and a cropped share PNG is the
  failure mode we are designing against.
- **No visual asymmetry between the panels.** Equal width (527px each), equal plate size, equal label
  weight, identical border treatment. If the recreation is styled as "the answer" and the original as
  "the evidence", the layout has made an accusation the copy then has to walk back.

Ship-blocking tests:

```
figure.disclaimer.fontSize === figure.panelLabel.fontSize
figure.disclaimer.color    === figure.panelLabel.color
figure.disclaimer is a descendant of the same bordered element as both panels
exported PNG height includes the disclaimer band  (assert on rendered pixels, not on the DOM)
```

### 7. Evidence rows

`@shadcn/item variant="outline" size="sm"`, laid out as `[locator] [title + citation] [verify →]`.

```
FONT-01   The face is the framework default                              verify →
          computed font-family resolves to Inter at 51.2px/800 ·
          read from the rendered page, not the stylesheet
```

- Locator (`FONT-01`) is Mono Medium 13 in `--accent`, and is a link to the rule definition.
- Title is Sans Medium 16, ink. Written as an **observation**, never a verdict. "The face is the
  framework default", not "AI-generated typography".
- Citation is Mono Regular 13, muted, and always contains a **measured value** plus **where it was
  measured**. `read from the rendered page, not the stylesheet` is not flavour text; it is the
  methodological line this whole product lives on, printed on every applicable finding.
- `verify →` expands a `collapsible` in place showing the raw payload — the computed style block, the
  byte range, the prompt. It never navigates away and never opens a modal, because evidence has to
  stay adjacent to the claim it supports.
- Rows have **no severity colour and no severity ordering**. Order is by rule ID, which is stable
  across runs, which means two receipts for the same artifact are diffable.

### 8. `inconclusive` and `not_assessed` — rendered honestly

These are the two states most products bury. Here they get a bordered band on the page surface
(`--surface`, so it reads as a note *on* the desk rather than another document), directly below the
evidence list, always rendered — even when empty, in which case it reads
`Nothing was withheld on this run. All 54 checks returned a measurement.`

| State | Chip | Body | When |
|---|---|---|---|
| `INCONCLUSIVE` | outline badge, Mono Medium 12, ink | *"The uploaded file is a screenshot. Re-encoding destroyed the signals we would otherwise cite, so we abstain rather than guess."* | A check ran and cannot produce a citable measurement. **Detected re-encoding/resampling forces this.** |
| `NOT ASSESSED` | outline badge, Mono Medium 12, ink | *"Motion, audio and typography-in-image were out of scope for this run. Absence of a finding here is not a finding."* | A check did not run. |

Rules:

- Both are set in **the same type and the same colour as a PASS finding**. Downgrading them visually
  is the dishonesty.
- Neither ever renders as an error, a toast, a greyed-out row, or an empty-state illustration.
- The sentence *"Absence of a finding here is not a finding"* is fixed copy and does not get
  rewritten for tone. It is the single most important sentence on the page for anyone who intends to
  use a receipt as an accusation.
- If **every** check is inconclusive, the receipt still renders in full — figure, bands, method
  button — with the headline replaced by `We could not do this one.` and the claim sentence
  explaining exactly which signal was missing. There is no "sorry, something went wrong" path,
  because nothing went wrong.

### Receipt empty state

Before an artifact is submitted, the receipt route renders `@shadcn/empty`:

- `EmptyTitle`: *"No receipt yet."*
- `EmptyDescription`: *"Paste a URL or drop a file. We will try to remake it and time ourselves doing
  it. You will see the same report we publish about our own site."*
- `EmptyContent`: the `input-group` (same control as the landing page) + a single ghost link,
  *"Or read a sample receipt."*
- No illustration. No icon tile. No "Get started" gradient panel.

## B. The landing page

Figma: `node-id=1-69`, 1440×1126.

### The job

**Run the detector on something in front of the visitor, immediately.** The thing it runs on is
**us** — the page scans itself, in the fold, and shows the result.

This is the single best decision available here and it does three jobs at once:

1. It is a live demo, satisfying "show, don't tell" without a video, a screenshot, or an explainer.
2. It is the marketing asset the founder already identified: *"we pass our own tool, here is the
   receipt."*
3. **It carries zero legal risk**, because the only artifact we judge above the fold is our own.
   Every alternative (scanning a famous site, a stock image, a sample from the corpus) names or
   implicates a third party in the first screen.

### First 3 seconds

1. **H1, 52px Regular:** *"This page has already been scanned by the thing it sells."*
2. **One line, 19px muted:** *"Not a score. We reproduce the artifact and show you how long it took.
   Below is the live result for this URL, run 12 seconds ago. Nothing is cached."*
3. **The live self-scan card** — `slopscorer.com · scan_ui · 54 checks` / `0 findings · 12 s ago ·
   re-run`, with four visible check rows in the exact `item` layout the receipt uses.

The visitor understands the mechanic before reading a feature list, because they have just watched it
run. The word "AI" does not appear above the fold.

### Hierarchy

| # | Block | Notes |
|---|---|---|
| 1 | Nav | Wordmark (Mono Medium 13, `+0.08em`), then `Method` · `MCP plugin` · `Our own receipt` · `Sign in`. Four items. No CTA button in the nav — the CTA is the whole fold. |
| 2 | H1 + one line | Max 940px / 760px measure. |
| 3 | **Live self-scan card** | White card, `--border-control`, radius 0. Header row + 4 `item` rows + a footer line on `--surface`. |
| 4 | Footer line inside the card | *"This is the same report any URL gets. We publish ours because a detector that cannot survive its own test is not worth running."* |
| 5 | The ask | `input-group`: `Paste a URL, or drop an image` + `Run it` (accent). 560px + button. |
| 6 | Legal note, 14px muted | *"We do not name creators. We do not assert that anything is AI. Read the method before you read a receipt."* |
| 7 | — fold at 1024px — | Everything above is proof, not pitch. |

Below the fold, in order: a real receipt for a real artifact (with the full disclaimer figure, so the
legal contract is visible before signup); the method, written plainly, including what we cannot do;
the MCP install (`curl`, macOS/Windows tabs); the Turing gauntlet as the second CTA; a short signed
founder note — one honest human line, per the corpus.

Deliberately absent below the fold: a logo wall, a pricing grid of three identical cards, a
testimonial carousel, a stats row of counters, and a "trusted by" strip. Every one is an identical-
card-grid tell, and with zero users any of them would be a fabrication.

### The self-scan must be real

The card is **not** a static screenshot of a good result. It calls the same `scan_ui` endpoint any
visitor's URL hits, against our own production URL, with the timestamp rendered from the response.
Non-negotiable, because the entire page is a claim about honesty and the first person to open
DevTools will check.

Consequences we accept: if a deploy regresses a check, **the landing page says so, in the fold, in
public.** That is the point. There is no client-side filter that hides a failing row. The header
counter renders whatever the run returned — `0 findings`, or `2 findings`.

If the scan endpoint is down, the card renders `INCONCLUSIVE` in the same treatment as the receipt:
*"We could not scan ourselves just now. That is a result, and we are showing it rather than a cached
one."* This is the honest failure path, and it is on-brand in a way a spinner never is.

### Landing empty state

There isn't one. A landing page with an empty state is a landing page that has not done its job. The
`empty` component is for the authenticated receipt route.

## C. Shared rules across both surfaces

- **No creator is ever named, depicted, or linked.** No avatars, no handles, no EXIF author, no
  "posted by". For a URL scan the URL is shown because it is the artifact locator and the user
  supplied it; for an uploaded image, source metadata is stripped before render and never displayed.
- **No word in the product asserts authorship.** Banned strings in UI copy: `AI-generated`, `fake`,
  `detected`, `confidence`, `probability`, `caught`, `slop` (in a verdict position — it is fine in the
  brand name, never in a finding).
- **One H1 per route**, verified in a browser at 390×844 and 1440×900, never by regex over the
  response body.
- Every `<img>` carries an `alt`. The artifact plates carry a description of *what is depicted*, and
  the recreation plate's alt begins `Recreation generated by Slop Scorer:` so a screen-reader user
  gets the disclaimer's substance without depending on the visual band.
- Real 404. `og:image` per route (the receipt's `og:image` is the figure **including** the
  disclaimer). Canonical. Sitemap. `lang`. No source maps. Zero console errors. No bare
  `*.vercel.app`.
