# @slop/notary

Attest the MAKING. Never the person.

## Why this shape, and not identity verification

`human-verification-licensing.md` is binding and its conclusion is short. Illinois BIPA is
$1,000-$5,000 per scan with a private right of action; Texas CUBI and Washington sit behind it; and
delegating a face match to a provider does not reliably move the liability, because directing the
collection can be enough. Identity verification is a service to outsource, never to build.

What is left is stronger anyway, and it is already a deployed standard. **RFC 3161 explicitly forbids
a timestamp authority from identifying the requester** - "the time-stamp request does not identify
the requester". An entire protocol for attesting that something existed at a time without attesting
who made it. That is our thesis, standardised, free, and unauthenticated.

So: no biometrics, no documents, no keystroke telemetry, no PII beyond an account id. A test walks
the source for field names that could hold any of it.

## The credential

Assembled from counts, run through a guard, and stored verbatim (a credential whose text can be
regenerated by later code is a credential nobody can be held to):

> We recorded 41 steps of this file's history, the first of them dated 2026-08-20T09:00:00.000Z. The
> root of that record, `<sha256>`, was timestamped by 3 independent authorities in 3 jurisdictions.
> The earliest of those timestamps is 2026-08-24T12:00:05.000Z, so the record existed by then. One
> authority we asked did not return a usable token. We checked that each authority returned a granted
> status over the exact root we submitted. We did not check the signature on any token against its
> authority's certificate chain. Each token is stored in full so it can be checked independently:
> `openssl ts -verify ...`. **A recorded process shows that a tool was operated over time. It does not
> show who operated it, and it does not show where the content came from. We make no claim about any
> person.**

The last two sentences are on every credential, unconditionally. `claims.ts` bans "verified human"
and the whole certification vocabulary outright, and requires any sentence naming a person to carry
a limitation in the same breath - the machine-checkable form of the finding that a person
transcribing model output produces a near-genuine process trace, so the most this evidence supports
is *a tool was operated*.

When nothing was stamped, the credential says so: *"No timestamp authority has stamped this chain,
so nothing here establishes that the record existed before now."*

## Multi-TSA fan-out

Four authorities, four operators, three jurisdictions, all free and account-free:

| id | url | jurisdiction |
|---|---|---|
| `sigstore` | timestamp.sigstore.dev | US, Linux Foundation |
| `belgium` | tsa.belgium.be/connect | BE, free EU-**qualified** government TSA |
| `freetsa` | freetsa.org | DE |
| `dfn` | zeitstempel.dfn.de | DE |

One authority is one entity's word, one jurisdiction's subpoena and one outage. A failure is
recorded with its reason and is **never fatal** - three tokens beat none, and the credential prints
the count rather than implying a set. Each result is checked for a granted status, an imprint equal
to the root we sent, and an unchanged nonce; a token stamping a different digest is rejected even
though it is otherwise valid.

`TOKEN_VERIFICATION_SCOPE` states the gap in data rather than in prose: the CMS signature is not
verified against the authority's certificate chain, and the raw DER is stored so a holder can close
that gap themselves. OpenTimestamps rides alongside as an additional anchor and is described as
pending, never as an anchor, because aggregation takes hours.

## Verification recomputes

`verifyCredential()` rebuilds the Merkle root from the event FIELDS (not from the stored leaf
hashes), re-parses every stored token against that root, and rebuilds the statement from the same
facts to compare byte for byte. It catches an edited event, a re-parented step, a removed step, a
swapped token, a genTime edited in the row, and a statement rewritten in the database. It touches no
network, so a holder can run it offline.

The chain uses RFC 6962 domain separation (`0x00` leaf, `0x01` node) and promotes odd nodes rather
than duplicating them, which is the CVE-2012-2459 shape. Inclusion proofs give selective disclosure:
show one step, prove it was in the record, disclose nothing about the others.

## Process recordings: the lane nobody verifies

Procreate records a time-lapse by default. Clip Studio Paint stores one inside the `.clip` file. No
product verifies either, and ArtStation's DMCA flow does not ask for one. `recording.ts` ingests that
shape of evidence: hash the frames, fold them into the chain, timestamp the root.

The container parsers are **minimal and say so**. A `.procreate` is a zip and a `.clip` is a SQLite
database; recognising the magic is done, extracting the frame streams is not, and every ingest
records `unparsedFields` naming what it could not establish. A recording read by a minimal parser
must not look like one read by a complete parser. Repeated identical frames are counted and
described as "what both a pause and a cut look like" - the count is defensible, an inference about
intent is not.

Chains are **private by default**. The Genshin case in the research is somebody taking a streamed
work-in-progress, running it through a generator and publishing first; a public process log is an
attack surface. Disclosure (`hashes`, then `full`) is an explicit act by the owner.

## Wiring it into `apps/web`

Not done here: `apps/web` belongs to another agent this session. Three routes:

```ts
// POST /api/notary/chains          → openChain({ ownerId })
// POST /api/notary/chains/:id/events → append(chainId, events) then stamp(chainId) then issue(chainId)
// GET  /notary/verify/:credentialId → verify(credentialId), rendered with formatVerification()
```

The verification page is the one that matters for distribution: it is the artifact a holder links
to, so it must render the credential's own words verbatim and show the per-authority table,
including the authorities that failed. Do not add a badge, a checkmark or a colour that reads as a
pass. Per `design/DESIGN.md`, the accent is for CTAs and moments, not for verdicts.
